# GC메디아이 AI-Native Engineer(인턴) 사전 직무테스트 - LLM 작업 지시서

## 1. 역할

당신은 실제 서비스 수준의 품질을 지향하는 소프트웨어 엔지니어다. 아래 요구사항에 따라 **영화 티켓 예매 시스템**을 설계하고 구현하라.

기능을 불필요하게 확장하지 말고, 필수 기능의 정확성, 데이터 정합성, 보안, 실행 재현성에 집중하라.

---

## 2. 최종 목표

회원이 가입 및 로그인한 뒤 영화와 상영 시간을 조회하고, 원하는 좌석을 예매하며, 자신의 예매 내역을 조회할 수 있는 실행 가능한 프로젝트를 완성한다.

---

## 3. 필수 기술 스택

- Server: Node.js
- Database: PostgreSQL
- Framework, ORM, Frontend 등 나머지 기술은 자유롭게 선택한다.

기술을 선택할 때는 과제 범위, 유지보수성, 구현 속도, 테스트 용이성을 고려하라. 선택한 기술과 선택 이유를 `README.md`에 기록하라.

---

## 4. 필수 기능

### 4.1 회원 기능

- 회원가입
- 로그인

최소한 다음 품질 기준을 충족하라.

- 사용자 식별값의 중복을 방지한다.
- 비밀번호를 평문으로 저장하지 않는다.
- 인증이 필요한 기능에 인증되지 않은 사용자가 접근하지 못하게 한다.
- 잘못된 입력이나 인증 실패에 일관된 오류 응답을 반환한다.

### 4.2 영화 및 상영 정보

- 영화 목록 조회
- 특정 영화 또는 조회 흐름에 맞는 상영 시간 목록 조회

영화와 상영 정보는 실제 데이터가 아니어도 된다. 애플리케이션을 실행한 뒤 기능을 바로 확인할 수 있도록 임의의 샘플 데이터를 제공하라.

### 4.3 좌석 예매

- 상영 회차의 좌석 선택 및 예매
- 로그인한 사용자의 예매 내역 조회

최소한 다음 품질 기준을 충족하라.

- 이미 예매된 좌석을 다시 예매할 수 없어야 한다.
- 동시에 같은 좌석을 예매하려는 요청이 들어와도 중복 예매가 확정되지 않아야 한다.
- 존재하지 않는 영화, 상영 회차, 좌석에 대한 요청을 검증한다.
- 예매 데이터와 사용자 및 상영 정보의 관계가 데이터베이스에 일관되게 저장되어야 한다.
- 예매 내역에는 사용자가 예매 내용을 식별하는 데 필요한 영화, 상영 시간, 좌석 정보가 포함되어야 한다.

## 5. 구현 원칙

### 5.1 범위

- 필수 기능을 우선 완성한다.
- 평가에 직접 도움이 되지 않는 과도한 기능은 구현하지 않는다.
- 추가 기능을 구현한다면 필수 기능의 완성도와 테스트를 해치지 않는 범위로 제한한다.

### 5.2 설계

- 회원, 영화, 상영 회차, 좌석, 예매의 책임과 관계가 드러나도록 데이터 모델을 설계한다.
- API, 비즈니스 로직, 데이터 접근 책임을 구분한다.
- 좌석 중복 예매 방지 전략을 데이터베이스 제약 조건과 트랜잭션 관점에서 설계한다.
- 입력값 검증과 오류 처리 방식을 일관되게 적용한다.

### 5.3 보안 및 운영 품질

- 비밀번호 해시, 인증 토큰 또는 세션 등 선택한 인증 방식의 기본 보안 원칙을 지킨다.
- 비밀값과 환경별 설정은 환경 변수로 분리하고 저장소에 하드코딩하지 않는다.
- 오류 응답에 비밀번호, 토큰, 내부 스택 트레이스 등 민감한 정보를 노출하지 않는다.
- 애플리케이션 및 데이터베이스를 다른 환경에서도 쉽게 실행할 수 있게 구성한다.

### 5.4 테스트

핵심 동작을 자동화된 테스트로 검증하라. 적어도 다음 시나리오를 포함한다.

- 회원가입 성공 및 중복 회원가입 실패
- 로그인 성공 및 잘못된 자격 증명으로 로그인 실패
- 영화 목록 및 상영 시간 목록 조회
- 좌석 예매 성공
- 이미 예매된 좌석의 중복 예매 실패
- 예매한 사용자의 예매 내역 조회
- 인증되지 않은 사용자의 보호된 기능 접근 실패

동시 예매 충돌을 처리하는 전략이 실제로 동작함을 테스트하거나, 재현 가능한 검증 방법을 문서화하라.

## 6. 구현 전 결정 사항

구현을 시작하기 전에 아래 항목을 결정하고 일관되게 적용하라.

- API 중심 백엔드만 구현할지, 최소한의 Frontend도 포함할지
- 사용할 Node.js 프레임워크와 ORM 또는 데이터 접근 방식
- 인증 방식
- 데이터 모델과 좌석 표현 방식
- 좌석 중복 예매 방지 방식
- 샘플 데이터 생성 방식
- 로컬 실행 및 테스트 환경 구성 방식

원문에서 정하지 않은 세부사항은 합리적으로 결정하되, 핵심 가정을 `README.md`에 명시하라. 필수 기술 스택과 요구 기능을 임의로 변경하지 마라.
